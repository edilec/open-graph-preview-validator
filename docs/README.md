# Input, rules and limits

The CLI takes `--root` and a root-relative `--page` HTML file. It reads only the document `<head>`; comment, script, style, template and noscript contents cannot supply metadata. Required fields are one `<title>`, one `<link rel="canonical" href="...">`, `og:url`, `og:title`, `og:image`, `og:image:alt`, `og:image:width`, `og:image:height`, `twitter:card`, `twitter:title`, `twitter:image`, and `twitter:image:alt`. `twitter:card` is `summary` or `summary_large_image`. Metadata attributes must be quoted. Common HTML character references in values are decoded before comparison. Unsupported markup yields `incomplete` rather than a guessed result.

URLs must be absolute HTTPS without credentials or fragments. The canonical and `og:url` must identify the same URL. The OG and X image URLs must match each other and share the canonical origin. Images may not use a query string because local file resolution cannot prove a transformed remote variant. The image URL pathname is decoded and mapped under the real root; its realpath must remain inside that root. The file must have a supported PNG signature and IHDR width/height, which are compared to the OG declarations. This is a PNG header check, not a full image decode, visual QA, hosted URL check, or platform renderer simulation. An image may still fail to render on a remote social platform. Direct library callers provide their own trusted `resolveImage` callback; only the CLI proves filesystem confinement.

stdout is one deterministic JSON report; stderr gives an operational summary. Findings sort by code unit on `(location.file, location.pointer, ruleId)`. `@page` and `@image` are logical provenance roles; `/head/tags/<ordinal>` points to the encountered head tag. Messages do not echo page titles, URLs, image paths or payloads. Exit 0 is a complete match, 1 is a definite validation failure, and 2 is bad invocation or incomplete required evidence. Bad invocation leaves stdout empty; unreadable or undecodable page content yields an `incomplete` JSON report. No files are written and no network request is made.

Limits: 262144 page bytes, 5242880 image bytes, 200 head tags, 20 attributes per metadata tag, and 5000 milliseconds from root resolution. N is accepted and N+1 is incomplete. The head parser is iterative and does not recurse into a DOM, so its recursion depth is zero; nested unsupported metadata is not treated as authoritative. The parser does not claim complete HTML5 error recovery.

Stable error rules: `duplicate-field`, `field-missing`, `image-description-missing`, `canonical-mismatch`, `title-mismatch`, `image-mismatch`, `image-dimensions-mismatch`, `reference-malformed`. Stable warning rules that force `incomplete`: `input-unavailable`, `input-too-large`, `input-invalid`, `tag-limit`, `timeout`, `image-unavailable`, `image-unsupported`.
